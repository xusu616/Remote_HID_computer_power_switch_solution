# 替代方案对比与选型参考

除了本仓库实现的 **Root 安卓旧机 USB HID 方案** 外，以下是几种常见远程唤醒方案的对比与适用场景。

| 方案 | 能否唤醒 S3 | 能否唤醒 S4/关机 | 是否依赖主机有线网卡 | 成本 | 稳定性 | 说明 |
| :--- | :---: | :---: | :---: | :---: | :---: | :--- |
| **Root 安卓旧机 (本方案)** | ✅ | ❌ (通常仅 S3) | ❌ | 0 元 (利用旧机) | 较高 | 需内核支持 `CONFIG_USB_F_HID`；自带电池当 UPS；配合 ACC 限充防鼓包 |
| **迷你 IP-KVM (NanoKVM / GL.iNet Comet)** | ✅ | ✅ (接 ATX 跳线) | ❌ | 200~400+ 元 | 极高 | 原生内置 Tailscale；支持屏幕画面、BIOS、模拟键盘及物理电源针脚短接；**台式机推荐 NanoKVM PCIe 版 (3.3Vaux 常电)** |
| **树莓派 Zero 2 W (USB Gadget)** | ✅ | ❌ | ❌ | 100~150 元 | 高 | 与本方案原理一致，用标准 Linux ConfigFS，无需处理 Android 杀后台和电池问题，但建议独立 `PWR` 供电 |
| **台式机加装 PCIe 有线网卡 + WoL** | ✅ | ✅ | ✅ (新网卡) | 20~60 元 | 极高 | 板载网口松了时的治本办法；走主板 PCIe 槽原生支持 WoL，局域网内用路由器/旧手机/ESP32-S3 发魔术包即可 |
| **手指机器人 (SwitchBot / Fingerbot)** | ✅ | ✅ | ❌ | 50~150 元 | 高 | 物理按开机键，不依赖任何系统与 USB 状态（但不适合长期合盖的笔记本） |
| **手机模拟蓝牙键盘** | ⚠️ 不稳定 | ❌ | ❌ | 0 元 | 低 | **不推荐**：多数主机 S3 会断掉蓝牙连接或下电，Linux 需专门给 `hci0` 开唤醒，且 Android 后台蓝牙 HID 易被回收 |
| **智能插座 + 通电自启** | ❌ 严禁 | ✅ (仅 S5 关机) | ❌ | 30~50 元 | 中 | **严禁在 S3 挂起状态下断电**，否则会丢失内存未保存数据相当于强制断电 |
| **关闭 Linux 自动休眠 (仅熄屏)** | 不需要唤醒 | — | ❌ | 0 元 | 最高 | 如果主机散热与待机功耗可接受，直接关闭自动挂起最省心 |

---

## 为什么不推荐用“手机蓝牙键盘”？

1. **S3 休眠极易断联**：大多数 Linux 主机的蓝牙模块挂在内部 USB 总线上，默认禁止唤醒，且许多蓝牙芯片/BlueZ 协议栈在主机进入 S3 时会主动断开现有 ACL 蓝牙连接；一旦断开，休眠中的电脑通常不会响应外设重新发起的蓝牙连接请求。
2. **Android 端后台保活困难**：`BluetoothHidDevice` API 需要应用维持蓝牙服务绑定，息屏挂后台时间长了容易被系统回收断连，难以像 Magisk root 守护进程 + `/dev/hidg0` 那样一条 HTTP 请求直接写内核设备节点完成唤醒。
